# Модель ученика

Что ученик знает — по узлам карты. Хранится во frontmatter заметок `model/<Тема>/<Узел>.md`, показывается дашбордом Bases `Прогресс.base` в корне хранилища. Идея уровня по доле верных ответов — из [RoundTable02/tutor-skills](https://github.com/RoundTable02/tutor-skills).

Модель отвечает на вопрос «держится ли **понимание** узла» и проверяется твоими квизами. Карточки (`cards/`) отвечают на «помнится ли **факт**», их ученик повторяет сам в Obsidian. Два расписания независимы: узлы считает `node-check.mjs`, карточки — плагин.

## Заметка узла

Имя файла — короткое имя узла с карты, уникальное в хранилище (по нему идут ссылки `[[…]]`). Без `: / \ # ^ | [ ]` в имени.

```markdown
---
type: узел
topic: <Тема>                       # ровно как в конспекте — по нему фильтрует Bases
conspectus: "[[<Тема> — конспект#<Заголовок раздела узла>]]"
depends_on:                         # рёбра карты: на чём узел держится
  - "[[<Узел-родитель>]]"
status: new                         # new | learning | shaky | solid
attempts: 0
correct: 0
last_checked:
interval: 0
next_review:
misconceptions: []
---

# <Узел>

Правило — в конспекте: [[<Тема> — конспект#<Заголовок раздела узла>]]
```

Текст правила в заметку узла **не копируй**: он живёт в конспекте. В заметке узла — только состояние.

## Статусы

| status | значит | кто ставит |
|---|---|---|
| `new` | на карте, ещё не проходили | ты, при создании после одобрения плана |
| `learning` | объяснён, проверки ещё не было | ты, когда начинаешь узел (правкой frontmatter, плюс `next_review` = сегодня) |
| `solid` | последняя проверка верная | `node-check.mjs … ok` |
| `shaky` | последняя проверка с ошибкой | `node-check.mjs … fail` |

## Запись результата — только скриптом

```
node .claude/hooks/node-check.mjs "model/<Тема>/<Узел>.md" ok
node .claude/hooks/node-check.mjs "model/<Тема>/<Узел>.md" fail --misconception "Что именно ученик думает неверно"
```

Скрипт сам увеличивает `attempts`/`correct`, ставит `status`, `last_checked`, считает `interval` (верно — удвоение, первый раз 1 день, потолок 120; ошибка — 1 день) и `next_review`. Даты руками не пиши.

- Один квиз-вопрос, проверяющий узел, — один вызов. Вопрос задевает два узла — вызов на каждый.
- Квизы зонда (фаза 1) по уже существующим узлам — тоже записывай: это измерение.
- **Заблуждение** формулируй как неверную модель в голове, а не как «ошибся в вопросе 3»: «Ставит だ во «выглядит»», «Считает, что градиент указывает на минимум». Одинаковые формулировки скрипт не дублирует — переиспользуй прежнюю, если это та же ошибка.
- Заблуждения — история. Не удаляй их, когда ученик исправился: `status` и доля верных уже это покажут.

## Уровень (цвет)

Доля `correct / attempts`: 🟥 < 40 % · 🟨 40–69 % · 🟩 70–89 % · 🟦 ≥ 90 % · ⬜ не мерили. Считает формула в Bases, во frontmatter не хранится.

## Блок прогресса в конспекте

Под заголовком конспекта, разделом `## Прогресс`, — встроенная база только по этой теме (`this.topic` — тема заметки, в которую база встроена):

````markdown
```base
filters:
  and:
    - file.inFolder("model")
    - 'type == "узел"'
    - 'topic == this.topic'
formulas:
  rate: 'if(attempts > 0, (correct / attempts * 100).round() + "%", "—")'
  level: 'if(attempts > 0, if(correct / attempts < 0.4, "🟥", if(correct / attempts < 0.7, "🟨", if(correct / attempts < 0.9, "🟩", "🟦"))), "⬜")'
properties:
  file.name:
    displayName: Узел
  formula.level:
    displayName: Уровень
  formula.rate:
    displayName: Верно
  next_review:
    displayName: Проверить
  misconceptions:
    displayName: Заблуждения
views:
  - type: table
    name: Узлы темы
    order:
      - formula.level
      - file.name
      - status
      - formula.rate
      - next_review
      - misconceptions
```
````
